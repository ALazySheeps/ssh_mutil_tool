验证日期：2026年10月11日。开发主机为Windows；Python3.13隔离环境、Paramiko4.0.0、Tk8.6；另有Ubuntu24.04.4 WSL2、Python3.12.3、glibc2.39。Windows Bash语义测试使用MSYS Bash5.3，Linux测试使用Ubuntu原生Bash及PTY。

## 自动化测试

执行命令：`python -m unittest discover -s tests -v`。本机设置 `SSHMT_TEST_BASH` 指向MSYS Bash，运行配置校验、持久化、SSH认证和指纹、本地真实SSH通道脚本传输、阶段控制协议、调度、编辑器和GUI恢复等测试。实际最终数量以本文件末尾的最终记录为准。

Windows测试中Linux socket与PTY测试跳过；Ubuntu WSL中全部执行。SSH集成测试服务器真实使用Paramiko协议；单独的Linux PTY测试执行了与实际远端相同的加载器，覆盖150 KiB脚本、source/export、中文与字面目录以及Ctrl+C。仍不把这些测试当作GNOME Terminal与RDK X5的端到端实测。

## 2026-10-15 GitHub CI 复查

GitHub PR 的首轮矩阵中，七个 Python 任务及 Ubuntu 24.04 都在同一项特殊路径桌面入口测试失败；Ubuntu 26.04 还出现 PTY 假超时。本地历史通过记录不能替代远程矩阵结果。

已在 Ubuntu 24.04 独立环境复现 GLib 无法读取原 Exec 的错误，修改入口生成方式后，同一路径通过桌面校验并实际启动。安装路径按字节编码为 Bash 字面量，避免路径中的引号、美元符号、反引号、百分号、反斜杠和换行经过不同 GLib 版本的字符串解析而改变。源码入口也改为实际启动验证。

新增真实 PTY 回归：子进程先关闭终端描述符、再延迟退出。修复前不到 0.1 秒就误报“8 秒超时”；修复后在原超时期限内继续等待进程退出并取得正确退出码。没有增加超时或跳过测试。

同步采用 `--token=<值>`，防止随机令牌以 `-` 开头时被当成新选项；已用真实子进程先重现参数错误、再验证能够进入 helper 模式。

2026-10-15 合入 CI 修复后复验：Ubuntu 22.04 / Python 3.10 / Tk 8.6 与 Python 3.11 / Tk 9 均完整通过 144 项测试、无跳过。

远端第二轮：四个 Ubuntu 和六个 Python 任务通过，Python 3.11 暴露 tmux 输出已写入而 pane_dead 尚未更新的测试竞争。通过输出后延迟退出的真实脚本稳定重现，改为限定时间内等待实际退出状态，并仍校验输出保留。本地完整 143 项重新通过、无跳过。
