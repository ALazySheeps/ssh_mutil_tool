# RDK X5 多终端 SSH 启动工具规格

版本：0.1，待评审。日期：2026年10月11日。

## 1 目标与使用假设

让开发者在本机图形界面选择目标设备和启动配置，一次输入 SSH 密码，一键打开多个本机终端，各自在 RDK X5 上配置环境并启动指定程序。配置可以在界面创建、编辑、保存、导入和导出，下次打开恢复上次选择。

默认部署方式：GUI 运行在 Ubuntu 桌面电脑，RDK X5 是远端 Ubuntu 设备。无需在设备安装本工具或常驻代理。如果需要 GUI 直接运行在带桌面的 X5 上，可后续提供 Linux ARM64 构建；首版不承诺该部署方式。

首版正式支持 Ubuntu 22.04、24.04 的 x86_64 桌面及 GNOME Terminal；其他桌面环境通过终端适配器扩展。远端要求 SSH 服务、Bash，以及用户命令需要的 ROS 2 和依赖。Windows 属于后续可选平台。

## 2 可行性评审

方案可行，主要难点在终端交互、执行语义和凭据传递，界面及配置保存本身难度较低。

| 原始设计 | 需要明确或调整的部分 | 采用的设计 |
| --- | --- | --- |
| 统一环境变量 | 一个连接中的 export 不会自动传播到其他 SSH 会话 | 公共初始化命令在每个窗口的同一个远端 Bash 中分别执行 |
| 输入终端命令 | source、cd、export 必须保持 shell 上下文 | 每窗口拼成一份脚本，在一个 Bash 进程中顺序执行 |
| 多条启动命令 | 前台常驻程序阻塞后续命令 | 每窗口通常只放一个常驻程序；多个程序使用多个窗口 |
| 多窗口启动 | 打开窗口并不代表 ROS 节点就绪 | 分开报告连接、初始化、程序执行和退出状态 |
| 自动记忆配置 | 配置内容保存与上次选择恢复是两件事 | 配置显式保存；目标和选择立即保存，并在退出时刷新 |
| 保存密码 | 明文配置不适合分享，也会泄露凭据 | 首版密码仅保存在本次运行内存中，配置文件不含密码 |
| 一键启动 | 首次连接需要验证服务器身份 | 首次展示主机指纹并确认；已信任设备正常一键启动 |

`RMW_IMPLEMENTATION=rmw_cyclonedds_cpp` 单独赋值不能保证子进程继承，应使用 `export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`。编辑器展示此提示，但不改写用户命令。

公共初始化适合 `source`、`export` 和快速检查命令；不应放启动常驻节点、重启设备等只应执行一次的操作，因为它会重复执行。编辑器须明确显示“每个窗口执行一次”。

ROS_DOMAIN_ID 和 DDS 参数属于用户提供的环境配置；工具不推断合适取值，也不保证网络发现成功。ROS 环境路径、工作空间、DDS 实现和网络应由用户按设备实际情况填写。

## 3 技术路线

| 方案 | 优点 | 成本及局限 | 结论 |
| --- | --- | --- | --- |
| Python、Tkinter、Paramiko、系统终端 | GUI 较轻，SSH 能力成熟，复用真实终端，开发及维护简单 | 需要终端适配与凭据通信；界面外观偏实用 | 推荐 |
| Python、PySide6、内嵌终端 | 集成界面更统一，窗口状态更集中 | 分发较大，还需可靠终端模拟器，普通文本框无法替代终端 | 未来可评估 |
| Electron 或浏览器加本地服务 | Web UI 开发方便 | 运行时较重；浏览器打开本机终端仍需本地组件 | 不符合首版轻量目标 |

采用 Python 3.10 及以上，GUI 使用 Tkinter/ttk，SSH 使用 Paramiko，配置使用标准库 JSON，分发使用 PyInstaller 的目录模式。Tkinter 是 Python 的 Tcl/Tk 接口；Paramiko 提供 SSH 客户端、伪终端和通道接口。[Tkinter 官方文档](https://docs.python.org/3/library/tkinter.html)，[Paramiko 客户端文档](https://docs.paramiko.org/en/stable/api/client.html)，[Paramiko 通道文档](https://docs.paramiko.org/en/stable/api/channel.html)。

这是针对本项目的工程取舍，包体和内存目标须由样机实测，不能仅由语言选择推定。PyInstaller 需按平台分别构建，Linux 包也需验证系统及架构兼容性。[PyInstaller 官方文档](https://pyinstaller.org/en/stable/)。

## 4 首版功能边界

首版包含连接管理、连接测试、密码认证、主机指纹管理、配置管理、多终端启动、窗口状态、失败提示、偏好恢复以及本地离线使用。所有窗口使用同一个目标和账号，每窗口有独立 SSH 连接。

首版不包含跨设备编排、文件同步、远端软件安装、自动重连重启程序、ROS 节点健康检测、依赖关系调度、后台托管以及一键强制停止全部远端进程。用户通过各终端的 Ctrl+C 停止前台程序。后续可增加密钥认证、系统钥匙串、tmux 持久会话及就绪检查。

## 5 界面与操作流程

### 主界面

连接区：已保存目标下拉框、目标名称、IP 或主机名、端口（默认22）、用户名、密码输入框和“测试连接”。密码默认遮蔽，提供临时显示。目标保存只保存连接信息。

配置区：配置下拉框、“导入”“新建”“编辑”“复制”“删除”“导出”。显示所选配置的窗口数量、公共初始化摘要和窗口列表。每行展示名称、启用状态、工作目录、启动延迟和本次运行状态。

底部：“一键启动”和事件信息。已知设备且密码正确时，一次点击即可启动。启动调度期间禁用重复点击；同一目标及配置仍有活动任务时阻止重复启动并提示先处理当前任务。状态无法确认时提示可能残留会话，用户可以明确选择再次启动。

### 配置编辑器

配置名称必填，说明可选。公共初始化用多行命令编辑区，支持粘贴 `source`、`export` 等 Bash 命令，并提供行号及语法说明。

“新建窗口”添加一个任务。每窗口填写名称、是否启用、可选远端工作目录、多行终端命令及启动延迟。支持删除、复制、上下移动。名称只用于显示，任务使用稳定 ID 标识。

命令区域是完整 Bash 片段，允许引号、管道、条件语句、换行和注释；不按空格拆词，不把每行分别执行。界面提示“后续命令会等待前一条前台程序结束”。

保存时校验结构及必填项，保留用户原始命令。未保存修改关闭时提供保存、放弃、取消。启动前如有未保存修改，要求用户选择保存并启动或取消，避免执行版本不明确。

### 典型操作

首次：启动工具 → 填连接信息 → 新建配置 → 填公共初始化 → 添加若干窗口 → 保存 → 一键启动 → 核验主机指纹 → 多终端执行。

后续：启动工具 → 自动恢复上次目标与配置 → 输入密码 → 一键启动。密码不跨应用重启保留。

## 6 执行语义

### 每窗口的顺序

1. 建立 SSH 连接并分配远端 PTY。
2. 在远端启动专用 Bash，不依赖交互式 `.bashrc` 自动加载。
3. 在该 Bash 中执行公共初始化。
4. 若指定工作目录，进入该远端目录。
5. 执行窗口命令。
6. 报告退出码并保持本机终端显示结果，提示按回车关闭。

所有初始化和任务命令都在同一个 shell 中执行，环境和当前目录可以延续。初始目录为远端用户 HOME；公共初始化的 cd 会影响后续步骤；窗口显式工作目录覆盖该结果。工作目录字段允许绝对路径或以 `~/` 开头的路径，其他相对路径拒绝；不对字段执行命令替换或任意变量展开。

脚本默认启用 Bash `set -e` 和 `pipefail`，不启用 `set -u`，减少环境初始化脚本兼容问题。失败停止当前窗口的后续执行，保留输出。`set -e` 在条件语句等场景有例外；完整 Bash 片段的退出语义由 Bash 决定，工具不宣称逐行绝对检测。允许预期失败时，用户应显式写条件处理或 `|| true`。

非交互 Bash 需明确执行 `source /opt/ros/<发行版>/setup.bash` 等初始化。需要 sudo 时，用户在对应终端交互输入，不自动把 SSH 密码作为 sudo 密码。

### 启动顺序与延迟

连接预检成功后，将该时刻作为本轮调度起点。所有启用窗口按列表顺序调度，每窗口延迟是相对于此起点的秒数；同延迟按列表顺序发起。延迟范围0至3600秒。窗口不会等待前一窗口的常驻程序结束。

延迟只提供粗略错峰，不能作为 ROS 就绪保证。需要可靠依赖时，可以在后续窗口命令中写带超时的检查脚本；工具首版不自动分析这些脚本。

预检失败不打开执行窗口。某窗口启动后失败，其他已经调度的窗口继续，各自报告结果；不自动回滚或自动重试。已启动任务不能因另一个窗口失败而被误杀。

### 状态与退出

每任务状态：等待、打开终端、连接中、初始化中、执行中、成功结束、失败、连接断开、状态未知。只有收到任务开始事件才显示执行中；该状态表示命令片段已经开始，不能证明节点健康。正常退出且退出码0显示成功结束，非零显示失败；断线无法得到退出码时显示连接断开。

状态事件走独立的本机通信通道，不靠匹配普通终端输出判断。记录本轮运行 ID、任务 ID、时间、阶段和退出码。终端宿主进程退出不能直接作为远端任务退出依据。

主 GUI 关闭后，已建立连接的独立终端继续运行；尚未启动的任务取消。退出前如有待启动任务，界面提示其将被取消。窗口完成后无需主 GUI 在线即可显示结果。重开 GUI 恢复配置选择，不在首版重新接管旧窗口。

关闭终端会关闭 SSH 会话，但不能保证所有远端子进程退出；`nohup`、后台化或服务管理器启动的程序可能继续运行。界面帮助应说明这一限制。可靠批量停止需要额外的进程生命周期管理，列入后续版本。

## 7 模块与连接机制

| 模块 | 职责与接口 |
| --- | --- |
| GUI | 编辑目标与配置，提交启动请求，展示状态；主线程只处理界面 |
| 配置存储 | JSON 读写、版本校验、原子保存、导入导出和偏好恢复 |
| 启动调度器 | 预检、生成本轮任务快照、延迟调度及重复启动防护 |
| 终端适配器 | 接收标题及 helper 参数数组，启动 GNOME Terminal；不拼接本机 shell 命令 |
| 会话 helper | 独立进程，取得任务凭据，建立 SSH，执行脚本，桥接输入输出并上报状态 |
| 本机会话服务 | 分发启动快照与短期凭据，接收状态事件，管理令牌生命周期 |

GUI 启动窗口时调用同一个可执行包的 helper 模式。Linux 使用用户私有运行时目录内的 Unix socket，目录权限0700、socket权限0600，并检查连接方同一用户身份。每任务使用一次性随机令牌，绑定运行和任务 ID；令牌不包含密码，取得启动快照后立即失效，未领取令牌60秒到期。helper 领取失败直接报错，不进入任务执行。

密码不出现在终端命令行、环境变量、配置文件、日志或临时脚本里；只通过本机受限通道从 GUI 内存传给 helper。任务脚本通过加密 SSH 通道传送，不在远端持久保存。密码登录后的 helper 不为重试长期缓存密码；Python 内存中的秘密不宣称能可靠清零。同用户恶意进程不属于此机制可完全隔离的边界。

主机信任检查在预检阶段进行，每个 helper 仍严格核对信任记录。未知指纹只在 GUI 中确认一次；已保存指纹发生变化时阻止连接，要求用户核验并在管理界面显式更新。不得无条件使用自动信任策略。

helper 在本机终端设置输入原始模式，将按键传到远端 PTY，持续读取输出，支持 Ctrl+C、方向键、中文输出和终端尺寸变化；任何异常都恢复本机终端模式。SSH 使用保活与连接、认证超时，超时可在高级设置调整，默认连接10秒、认证15秒、保活15秒。执行常驻任务不设置统一运行时限。

该终端桥接是实现风险最高的模块，应先验证交互、输出流控、终端缩放、断线和 GUI 退出行为，再实现完整编辑器。[Paramiko 通道文档](https://docs.paramiko.org/en/stable/api/channel.html)说明了 PTY、通道生命周期及持续读取输出的重要性。

## 8 配置格式与保存

采用 UTF-8 JSON，扩展名 `.json`，格式版本为1。连接目标独立于启动配置，以便相同配置在不同设备使用。示例中路径及包名须按实际设备修改。

```json
{
  "schema_version": 1,
  "id": "rdkx5-demo",
  "name": "RDK X5 开发启动",
  "description": "启动驱动和业务节点",
  "common_init": "source /opt/ros/humble/setup.bash\nsource ~/robot_ws/install/setup.bash\nexport ROS_DOMAIN_ID=10\nexport RMW_IMPLEMENTATION=rmw_cyclonedds_cpp",
  "windows": [
    {
      "id": "driver",
      "name": "驱动",
      "enabled": true,
      "working_directory": "~/robot_ws",
      "commands": "ros2 launch my_driver bringup.launch.py",
      "start_delay_seconds": 0
    },
    {
      "id": "application",
      "name": "业务脚本",
      "enabled": true,
      "working_directory": "~/robot_ws/scripts",
      "commands": "python3 main.py",
      "start_delay_seconds": 3
    }
  ]
}
```

保存目录：`${XDG_CONFIG_HOME:-~/.config}/ssh-multi-tool/`，包含 `profiles/`、`targets.json`、`preferences.json` 和本工具专用 `known_hosts`。默认不修改系统 SSH 配置。运行状态不写入可分享配置。

偏好记录 `last_target_id`、`last_profile_id`、窗口尺寸和终端选择。目标或配置选择变化即原子保存；正常退出再次刷新，因此崩溃不会丢失已保存选择。启动时配置已删除或损坏则显示提示并回退到可用选项；从不自动执行配置。

导入将文件校验后复制到内部目录，避免外部文件移动导致选择丢失；ID 冲突提供新副本或明确覆盖，默认新副本。导出只含配置，用户自写命令中的秘密无法自动保证被识别，界面提示检查后再分享。

格式校验：版本支持、ID唯一、名称非空、至少一个启用窗口、启用窗口命令非空、延迟为有效数值、字段类型正确。未知版本拒绝并解释；未知字段拒绝以防拼写错误。首版每配置最多32个窗口，单配置文件最多1 MiB。JSON 中的 `\n` 在界面显示为真实换行。

保存采用同目录临时文件、刷新、原子替换；失败保留旧版本并展示错误。配置目录仅当前用户可读写。配置变更不影响已启动任务，本轮使用不可变快照。

## 9 异常提示与安全边界

错误须说明目标、窗口、阶段和可操作原因，例如“驱动窗口：工作目录不存在”“密码验证失败”“找不到 GNOME Terminal”。环境命令失败应给出窗口及阶段，具体错误保留在终端；配置预检不会为验证而执行用户命令。

网络与 SSH 操作放在后台，GUI 保持可操作。持续读取远端输出，避免大量日志阻塞；界面只保留有上限的状态事件，不复制所有终端内容到内存。首版诊断日志只记元数据及错误类别，不记密码、完整命令、终端输入和完整输出。

配置本质上可以执行任意远端 Bash 命令。导入时展示完整公共初始化和窗口命令供检查；导入或选中配置本身不执行任何命令。IP、用户名、目录、窗口标题等字段不得成为本机 shell 拼接内容。远端命令属于用户明确提供的执行内容，应原样保持语义。

## 10 分发与快速使用

提供 Ubuntu x86_64 压缩包，解压后运行启动器；包内包含 Python 运行时、Tk、SSH 依赖、示例配置和中文快速入门。优先目录模式以便排查资源及依赖问题，不要求用户安装 Python 或 pip。可选提供 `.deb` 桌面入口。

GUI 启动时检查 GNOME Terminal；缺失时显示明确安装说明及支持的平台信息。包应能从带空格及中文的路径运行，配置存入用户目录，程序安装目录无需可写。远端只要求已有 SSH、Bash、ROS 2 及用户程序依赖。

快速入门控制在一页：解压启动、填目标、导入示例、修改 ROS 与工作空间路径、保存、启动、查看输出及 Ctrl+C 停止。首次上手不要求阅读源码。分发同时带许可证和第三方依赖许可清单。

Ubuntu 22.04 与24.04须分别验证；构建兼容基线以22.04为起点，但不以此替代24.04实测。Windows 后续需 Windows Terminal 或控制台适配、本机安全通信及终端输入适配，并单独构建验证；不得仅凭 Python 跨平台就宣称支持。

## 11 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 首次使用 | 干净 Ubuntu 桌面无需 Python/pip 即可打开；示例及缺失依赖提示可用 |
| 基本启动 | 一个密码启动三个独立终端，分别执行 ROS 命令、Python脚本和Shell脚本 |

| 错误处理 | 密码错误不启动任务；初始化失败阻止当前任务；失败窗口保留输出 |
| 终端交互 | Ctrl+C停止典型前台脚本和ROS节点；方向键、交互输入、缩放正常 |
| 配置管理 | 创建、复制、编辑、删除及导入导出一致；错误JSON和版本不覆盖旧配置 |
| 记忆选择 | 正常退出及选择保存后异常退出，重开恢复目标和配置；密码为空 |
| 凭据与信任 | 密码不见于进程参数、配置、日志及临时文件；主机指纹变化阻止启动 |
| 生命周期 | GUI退出后活动终端继续；未启动任务取消；断线不自动重启远端程序 |
| 并发及日志 | 六窗口持续输出30分钟，界面响应，无无限内存增长或输出读取死锁 |
| 路径兼容 | 本机及远端带空格、中文的路径可用；本机字段中的shell字符不被执行 |

性能设计目标：在记录了硬件及系统版本的普通开发电脑上，冷启动至主界面可操作不超过3秒，GUI空闲内存目标不超过100 MiB；终端及其进程另行统计。性能是待实现验证的验收目标。SSH建立耗时依赖网络，不计入本地冷启动指标。最终发布须列出实际包体和资源数据。

## 12 评审结论与待确认假设

推荐先完成 Ubuntu 本机 GUI、系统多终端及密码认证闭环，再扩展 Windows 和后台托管。这能直接覆盖 RDK X5 开发场景，并保持远端零代理部署。

本规格按以下假设设计：GUI运行在开发电脑；首版采用独立终端窗口；密码每次打开工具输入一次；公共初始化在每窗口重复执行；结束程序主要通过各终端Ctrl+C；启动延迟不保证业务就绪。若这些假设需要变化，应在实现前调整相关规格。

本轮交付为可评审规格，不包含实现代码或已经验证的运行产品。
