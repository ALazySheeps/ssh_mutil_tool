# SSH 多终端工具快速入门

在Ubuntu桌面操作，目标设备开启SSH服务。

## 打开工具

Ubuntu24.04 x86_64可先解压测试包 `ssh-multi-tool-0.1.0-ubuntu24.04-x86_64.tar.gz`，在解压目录执行 `./ssh-multi-tool`，无需Python/pip。此包已验证WSL中的GUI及helper启动，真实桌面与X5端到端仍需验收；Ubuntu22.04先使用源码版。

源码版准备依赖并运行：

```bash
sudo apt install python3 python3-tk python3-venv gnome-terminal fonts-noto-cjk libglib2.0-bin libatspi2.0-0
bash install-ubuntu.sh
bash start.sh
```

运行需要GNOME Terminal；缺失时安装 `sudo apt install gnome-terminal`。

## 先验证连接

填写设备名称、IP、端口22、用户名和密码。点击“测试连接”，首次连接通过可信渠道核对指纹，再确认信任。

导入 `examples/smoke-test.json`，检查命令并保存，点击“一键启动”。一个窗口显示环境变量和设备信息，另一个持续输出时间；在第二个窗口按Ctrl+C停止，按回车关闭。

## 创建 RDK X5 配置

点击“导入示例”。在“公共初始化”修改ROS发行版、工作空间路径、ROS_DOMAIN_ID及DDS实现。初始化使用 `source` 和 `export`，每窗口执行一次。

在“终端窗口”新建或编辑窗口，填写远端工作目录及终端命令。多个常驻节点分窗口。工作目录支持 `/绝对路径`、`~/目录` 或留空；延迟只用于错峰。

保存后返回主界面，点击“一键启动”。常驻程序在各终端Ctrl+C停止。执行中只表示命令已经开始，需要自行确认业务是否正常。

## 打开独立远程终端

填写目标设备和密码后，点击窗口列表下方的“打开远程终端”。验证SSH连接后会打开可手动输入命令的窗口。选择了启动配置时，会先执行当前配置的公共初始化，继承其中的环境变量和目录，再进入交互Bash；初始化失败会保留错误结果。新终端不执行配置窗口的启动命令。未选择配置时仍可打开普通SSH终端。

可以重复点击打开多个窗口，已有窗口继续运行；切换目标后可以连接另一台设备。独立终端统一显示在“手动终端”标签页，切换启动配置后仍可选中并关闭或重启，也会被“一键关闭”关闭。确认窗口关闭后会自动删除列表条目和对应管理记录；直接关闭终端窗口也会清理。程序结束后仍停留在结果页的窗口会保留到实际关闭。配置定义的窗口在“配置窗口”页管理，关闭会话后配置行仍保留。重启时需选回该窗口原先连接的目标并输入其密码。

## 特别调试窗口

启动配置区域提供四个特别调试快捷按钮。点击“配置调试窗口”，填写每个槽位的名称和命令并保存；可以输入多行 Bash 命令。四个槽位是本机通用设置，所有开发板共用，不属于启动配置文件。第一个槽位默认是 `htop`，其他三个留空；远端需已安装对应命令。

选择目标、启动配置并输入密码，点击槽位按钮。工具会先执行当前配置的公共初始化，再在继承的环境和目录中运行调试命令，初始化失败则停止。窗口显示在“手动终端”页，可关闭、重启或一键关闭，实际关闭后自动清理。修改槽位后，新窗口使用新命令，已有窗口重启仍沿用启动时的命令和初始化配置。

## 单独启动配置中的窗口

在当前配置的列表中选中一个启用的窗口，点击“启动所选窗口”。工具会验证SSH连接，立即执行公共初始化、窗口工作目录切换和启动命令，不等待批量启动延迟，也不启动其他窗口。

已有活动会话或等待任务的窗口不能重复启动；状态未知时需先关闭。可以逐个启动同一目标、同一配置中的不同窗口；若其他目标或配置有活动任务，需先关闭。新启动使用当前已保存的配置，重启使用该窗口上次启动的配置快照。

## 按开发板集中管理会话

同一主机、SSH端口和用户的会话集中在一个GNOME Terminal窗口，配置任务、普通SSH和调试任务各使用一个标签页；不同开发板分别使用窗口。关闭某个标签页后，其他标签页继续运行；关闭GNOME整个窗口会断开该开发板窗口中的全部会话。主界面的“关闭会话”和“重启会话”只处理选中的会话。

特别调试按钮默认复用同一开发板、同一槽位的活动会话，不重新验证密码或重复执行命令，并在“手动终端”页选中已有会话。工具会尝试切换对应终端标签页并聚焦窗口；若桌面辅助功能或窗口管理器阻止聚焦，会显示提示，此时手动切换终端即可，会话仍然被复用。需要额外会话时，右键槽位按钮选择“新开会话”。已结束的调试任务再次点击会新建会话；重启工具不会接管旧终端。

## 断线保活

远端安装好 tmux 后，勾选“断线保活（tmux）”，再启动窗口。配置任务、普通远程终端和四个特别调试槽位都支持，公共初始化在新建 tmux 会话时执行。开关只影响新窗口。

断网、关闭终端或点击“一键关闭”后，程序仍在目标中运行。选择列表中的保活窗口，点击“重新连接”即可恢复原会话，不会重复运行初始化和命令；保活手动窗口断开后保留列表条目。重新连接需要输入原目标的密码。

需要结束程序时点击“停止程序”；需要重新运行命令时点击“重启会话”。已结束的命令保留输出面板，重连只查看原输出。原会话不存在时，重连报错，需明确重启。保活配置窗口仍占用当前批次，切换启动另一批配置前须停止；手动终端仍可连接多个目标。

主界面重开后，相同目标和配置窗口、相同调试槽位的保活启动会复用原 tmux 会话。额外手动窗口的管理记录仅保留在本轮主界面；退出后可在开发板上运行 `tmux -L ssh-multi-tool list-sessions` 查看，再执行 `tmux -L ssh-multi-tool attach-session -t <会话名称>` 恢复。开发板重启会丢失 tmux 会话。

## 关闭和重启窗口（普通模式）

在主界面的窗口列表选中窗口，点击“关闭会话”关闭该终端；尚在延迟等待的窗口会取消启动。点击“重启会话”会先验证本轮目标的密码，关闭旧SSH会话，再立即按本轮原配置重新运行公共初始化和窗口命令，不重复等待启动延迟。其他窗口继续运行。

点击“一键关闭”关闭本工具打开的全部窗口，包括已结束但仍显示结果的窗口，同时取消延迟任务和进行中的启动/重启。退出主界面仍会保留已启动的终端。

关闭窗口会断开SSH；通过nohup、后台化或服务启动的远端程序可能继续运行。重启前请自行确认这些程序的状态。

## 下次使用与分享

下次自动选中上次目标和配置，只需重新输入密码。导出配置为JSON发给他人，分享前检查自写命令是否含秘密；对方导入后修改设备路径即可使用。

关闭主界面后已有终端继续执行；后台化程序也可能在断线后运行，重新启动前检查已有任务。

WSL或最小化Ubuntu若中文显示为方框，请运行 `sudo apt install fonts-noto-cjk`，关闭工具后重新打开。预编译包也依赖系统中文字体。
